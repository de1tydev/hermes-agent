# Issue 正文模板

所有正文都使用 **Jira Wiki Markup**，不要使用 Markdown。

## 快速规则

- 二级标题：`h2.`
- 三级标题：`h3.`
- 列表：统一使用 `*`
- 引用：`{quote}...{quote}`
- 代码块：`{code}...{code}`
- 加粗：`*text*`
- 当前 Jira 实例里，**不要**在正文中使用 `#` 编号列表；它可能被误渲染成标题
- 普通 issue 正文里，**不要**使用 `h1.`；默认只用 `h2.` / `h3.` 做结构标题
- 若正文里需要写公式 / 约束 / 伪公式，**不要**写 LaTeX / MathJax；统一改成 ASCII 可读形式，并放进 `{code}` 块

推荐把正文先写入 `/tmp/issue_body.jira`，再通过 `--template` 创建：

```bash
jira issue create -p TEAP -t "新功能" -s "标题" -C 算法 --template /tmp/issue_body.jira --no-input
```

## 模板一：Bug / 故障

```text
h2. 问题现象

简要描述用户看到的异常现象。

h2. 复现路径

* 步骤 1
* 步骤 2
* 步骤 3

h2. 实际结果

当前系统的错误表现。

h2. 期望结果

修复后应达到的正确行为。

h2. 影响范围

* 受影响模块
* 受影响角色 / 页面 / 接口 / 算法
* 是否阻塞关键流程

h2. 补充信息

* 环境信息：如 develop / test / prod
* 若有报错日志、接口返回或截图说明，可补在这里
```

## 公式 / 约束写法

Jira Wiki Markup 不提供稳定的 LaTeX / MathJax 渲染能力。后续只要正文里涉及公式、约束、上下界、目标函数、伪代码式数学表达，统一按下面的方式写：

```text
{code}
-c_trans(l,tau) * P_ac(l,tau) <= C_trans(l,tau)
C_trans(l,tau) <=  c_trans(l,tau) * P_ac(l,tau)
{code}
```

### 公式写法规则

- 优先使用 ASCII 变量名：如 `tau`、`alpha`、`beta`，不要依赖希腊字母渲染
- 一条约束一行；不要把多条不等式连写在同一行
- 乘号优先写 `*`；上下界优先写成两行，避免歧义
- 若确实需要保留原符号，可在 `{code}` 块内使用 `<=` / `>=` / `!=` / `->` 这类纯文本运算符
- 不要在 Jira 正文里直接写 `$...$`、`\(...\)`、`\[...\]`、`\frac`、`\sum`、`\min`、`\max`、`\begin{}` 这类 LaTeX 语法
- 不要指望 `^` / `_` 在正文里按数学上标下标稳定渲染；需要时直接改写进变量名或放进 `{code}`
- 更完整的改写映射与 TEAP 示例，见 `references/jira-formula-ascii-cheatsheet.md`

## 使用建议

- 不要把口语化聊天原文直接塞进 Jira；先结构化，再套模板
- 若已经发现相关旧 Issue，可在正文最后补一段 `{quote}` 说明与旧 Issue 的关系
- 若正文很长，优先用模板文件，不要直接在命令行里拼多行文本
- 生成完正文后，先跑 `python3 {baseDir}/scripts/lint_jira_markup.py /tmp/issue_body.jira`
- 若 lint 提示 `#` 列表、`h1.` 或 LaTeX 语法，不要硬提交；先改成 `*` 列表、`h2.` / `h3.` 或 `{code}` + ASCII 公式再创建
