## 权威范围与术语

本文按 TEAP Core `develop` 的以下契约整理：

- `teap/config/sim_job_config.yml`：当前正式配置的计算模式及名称；
- `db_utils/models/task_table.py`：任务数据库中的 `job_type_id` 枚举；
- `app/teap_api_v3/views/upload_case_file_view.py`：普通 `.tc/.tr` 和 BPA 作业的公开启动入口；
- `app/schedule_task/task_listener.py`：调度器实际采用的求解与结果处理分支。

最近一次核验的 Core 提交为 `367095ff8ef2d1111ae900c61a015ae651393710`。实际操作前仍运行以下命令查看当前 CLI 同步的类型；若文档、CLI 和目标服务不一致，停止启动并报告版本差异，不要猜一个 ID：

```bash
teap task job-types
```

区分三个概念：

- **计算模式**：算法配置名，例如 `mid_term`、`market`；
- **作业类型**：提交和任务记录使用的整数 `job_type_id`；
- **任务**：某个输入按一个 `job_type_id` 执行后形成的一次记录。

相同 `.tc` 不一定满足所有模式的模型、参数、许可或求解器前置条件。`task job-types` 表示 CLI 已同步的类型集合，不表示目标服务、当前用户或当前 case 一定能运行全部类型。

## 当前计算模式总表

`sim_job_config.yml` 当前配置 10 种模式：

| `job_type` | 配置名 | 简称 | 分类名称 | 完整名称 | 调度执行族 |
| ---: | --- | --- | --- | --- | --- |
| `3` | `short_term` | 滚动 | 滚动模拟 | 滚动模拟 | 常规仿真 |
| `4` | `mid_term` | 平衡 | 时序模拟 | 中长期电力电量平衡 | 常规仿真 |
| `5` | `long_term` | 规划 | 协同规划 | 源网荷储协同规划 | 常规仿真 |
| `6` | `capacity_balance` | 容平 | 容量平衡 | 容量平衡 | 容量平衡 |
| `101` | `ac_power_flow` | 潮流 | 潮流计算 | 潮流计算 | 电网静态计算 |
| `102` | `n_1` | N-1 | N-K故障 | N-1故障 | 电网静态计算 |
| `103` | `n_2` | N-2 | N-K故障 | N-2故障 | 电网静态计算 |
| `104` | `short_circuit` | 短路 | 短路故障 | 短路计算 | 电网静态计算 |
| `105` | `topo_opt` | 重构 | 配网优化 | 配网优化 | 电网静态计算 |
| `301` | `market` | 市场 | 市场模拟 | 市场模拟与电价出清 | 常规仿真/市场 |

调度器把 `3/4/5/301` 交给仿真结果路径，把 `6` 交给容量平衡路径，把 `101-105` 交给电网静态计算结果路径。这个分组影响输入参数、求解过程和结果结构，不能用一个模式的 result group 推断另一个模式。

## 启动入口与输入类型

### 普通 case/result 入口

Core 的 `/backend/teap_api_v3/upload_case_file/` 接受：

```text
3, 4, 5, 6, 101, 102, 103, 105, 301
```

通常输入服务端 `.tc`：

```bash
teap task start "$CASE_PATH" --job-type 4
```

启动前按 [SKILL.md 的校验节奏](../../SKILL.md#校验节奏) 执行唯一的提交门禁。

只有 `301` 还允许把已有服务端 `.tr` 作为输入。CLI 会根据后缀将它作为 `tr_file_name` 提交：

```bash
teap task start "$ROLLING_RESULT_PATH" --job-type 301
```

不要把其他 job type 与 `.tr` 组合，也不要把本地 `.tr` 未经确认地当成服务端结果路径。

### BPA 专用入口

Core 的 `/backend/teap_api_v3/upload_bpa_file/` 接受 `101/102/103/104`。其中 `104` 只在该入口中启动，需要：

- BPA `.DAT` 文件；
- `.SWI` 文件；
- 按分区或所有者二选一的扫描范围；
- 最小、最大电压范围；
- 至少选择单相短路或三相短路之一。

当前通用 `teap task start` 固定调用普通 case/result 入口，尚未封装 BPA 专用启动参数。因此：

- 不要执行 `teap task start something.tc --job-type 104`；Core 会拒绝该组合；
- `task job-types` 中出现 `104` 只表示同步了 Core 类型，不表示普通启动命令支持它；
- 用户要求启动 BPA/短路计算时，明确报告当前 CLI 缺少专用提交命令；不要用 `curl` 绕过 CLI，也不要改试 `101/102/103`；
- 已存在的 `104` 任务仍可通过通用 `task status`、`task wait`、`task cancel` 和适用的结果查询命令处理。

## 仿真与规划类

### `3`：滚动模拟（`short_term`）

用于滚动或精细化时序生产模拟。以 `.tc` 为输入，结果通常包含完整时序、系统/分区工作位置以及设备级曲线，适合查询具体时刻、极值时刻和设备运行状态。

不要把“滚动”理解为自动重复提交多个 CLI 任务；滚动逻辑属于该作业的 Core 算法。结果分析先动态运行 `result groups`，不要套用中长期月度代表时刻作为唯一时间维度。

### `4`：中长期电力电量平衡（`mid_term`）

用于中长期时序模拟和电力电量平衡分析。以 `.tc` 为输入，可携带 `--chronology-reduction-method partial`；Core 当前只接受 `partial` 这一显式值，未指定时由仿真入口按模式处理默认值。

常见结果包括关键摘要、成本与惩罚、电量平衡、月度风险代表时刻、任意小时平衡、工作位置及设备曲线。月度默认表不是全部时序；任意小时和设备级查询见 [teapresult/query-recipes.md](../teapresult/query-recipes.md)。

### `5`：源网荷储协同规划（`long_term`）

用于源网荷储协同规划。以 `.tc` 为输入，也可使用 `partial` 时序削减。Core 在入队前检查规划设备；case 没有规划设备时会拒绝启动。

遇到缺少规划设备的业务失败时，停止原样重试，先读取设备表和规划参数确认用户确实要执行规划。不要降级成历史 `job_type=1`，也不要擅自改为 `4`。

规划结果与运行仿真结果的目标不同。先以动态 inventory 确认可用摘要、规划设备和运行曲线，再选择 result group。

## 容量平衡类

### `6`：容量平衡（`capacity_balance`）

用于容量充裕性或容量平衡计算。它有独立的求解和结果处理路径，不是 `4` 的简化名称，也不是普通逐时功率平衡的同义词。

以 `.tc` 为输入。分析时先发现实际 result groups；不要假设一定存在滚动模拟设备曲线、中长期月度表或市场电价字段。

## 电网静态计算类

### `101`：潮流计算（`ac_power_flow`）

用于交流潮流计算。Core 同时允许普通 `.tc` 入口和 BPA `.DAT` 入口。当前 CLI 的 `task start` 只覆盖普通 `.tc` 路径。

### `102`：N-1故障（`n_1`）

用于单一元件退出的 N-K 故障分析。Core 同时允许普通 `.tc` 和 BPA `.DAT` 路径；结果进入 N-K 故障处理分支。不要把名称中的 `N-1` 当作任务重试次数或时序场景编号。

### `103`：N-2故障（`n_2`）

用于两个元件组合退出的 N-K 故障分析。输入路径与 `102` 类似，但组合规模、耗时和结果数量可能明显更大；用户未明确要求时不要用 `103` 代替 `102`。

### `104`：短路计算（`short_circuit`）

用于短路故障扫描。它是当前正式配置模式，但只能通过 BPA 专用入口启动，不在普通 `.tc` 入口的允许列表中。扫描范围与故障类型是必填业务配置，具体约束见“BPA 专用入口”。

### `105`：配网优化（`topo_opt`）

用于配网拓扑优化/重构。通过普通 `.tc` 入口启动，并使用 `job_config_dict` 接收任务级优化参数；Core 会将提交值与配网优化默认参数合并。

不要凭字段名猜 `--job-config-json`。先读取目标服务/任务约定或已有配置，确保键名和值类型准确。

## 市场模拟类

### `301`：市场模拟与电价出清（`market`）

支持两种输入工作流：

1. 输入 `.tc`，直接执行市场模式仿真并生成 `.tr`；
2. 输入已有滚动/短期 `.tr`，在既有运行结果基础上进行市场定价并生成新的 `.tr`。

第二种方式不是“下载 `.tr` 后手工解析”：应直接把服务端滚动结果路径提交为 `301` 的输入。两种工作流最终都形成新的 task/result。

市场结果可能保留滚动结果结构，并增加节点边际电价、能量和阻塞分量，以及可选的机组经济性和价格统计。不要套用中长期摘要路径；先运行：

```bash
teap result market groups <task-id-or-result-path>
```

完整查询方法和市场结果与滚动/时序结果的差异见 [teapresult/market-results.md](../teapresult/market-results.md)。

## 历史与内部类型

任务数据库枚举仍保留：

| `job_type` | 枚举含义 | 当前定位 |
| ---: | --- | --- |
| `0` | 时序模拟 | 历史兼容值 |
| `1` | 协同规划 | 历史规划工作流值 |
| `2` | 规划转时序 | Core 内部规划结果转时序值 |

它们没有出现在当前 `sim_job_config.yml`，也不被普通公开启动入口接受。`2` 仍可能由 Core 内部的规划转时序流程创建，因此可在历史任务中看到。

不要把 `0/1/2` 提供为新的 `task start --job-type` 选项；不要因为 `3/4/5` 启动失败就尝试对应的旧编号。

## 选择和执行护栏

按用户研究目标选择模式，不按“看起来相近”替换：

| 用户目标 | 首选类型 | 先确认 |
| --- | ---: | --- |
| 滚动生产模拟、完整时序运行状态 | `3` | case 时序和运行参数 |
| 中长期电力电量平衡 | `4` | 时序范围及是否使用 `partial` |
| 源网荷储规划 | `5` | 规划设备和规划参数 |
| 容量充裕性/容量平衡 | `6` | 目标确为容量而非逐时功率平衡 |
| 潮流 | `101` | 输入是 `.tc` 还是 BPA `.DAT` |
| 单故障或双故障分析 | `102` / `103` | N-1 与 N-2 的明确选择 |
| 短路扫描 | `104` | BPA 输入、扫描范围和故障类型；当前 CLI 不可启动 |
| 配网拓扑优化 | `105` | 准确的任务配置字典 |
| 市场出清/节点电价 | `301` | 新 `.tc` 仿真还是已有滚动 `.tr` 定价 |

执行前：

1. 运行 `teap task job-types`，确认 CLI 类型定义；
2. 确认输入后缀、服务端路径和对应启动入口；
3. 对普通 `.tc` 按 [SKILL.md 的校验节奏](../../SKILL.md#校验节奏) 在启动前执行一次提交门禁；
4. 明确模式专属前置条件后才启动；
5. 失败时按结构化 `error.code`、`retryable` 和 `hints` 行动，不换相近 job type 盲试；
6. 完成后按 job type 动态发现结果，不以另一模式的固定 group 判定“没有结果”。

任务查询可以按类型过滤：

```bash
teap task status --finished-only --job-type 4
teap task status --unfinished-only --job-type 301
```

筛选只影响任务列表，不改变任务类型，也不能证明输入适合该模式。
