## 已覆盖的算法和模型能力

- job type 3/4/5/6、101/102/103/104/105、301；使用 `task job-types` 查看。
- `gen/gen_plan` 指定 `p_rate` 曲线及输入范围校验。
- TMY、负荷预测、风光极端曲线生成和绑定。
- 年内与跨年机组检修计划生成、上传、插入。
- 短期结果的运行方式场景查询、典型方式提取和 XLSX 下载。
- `dsm/dsm_plan`、`hydro_acc/hydro_acc_plan`、`csp_plan` 后端初始化字段。
- 完整 sheet/row/parameter/timeseries 通用读写，可表达算法新增字段。
- 时序裁剪/告警、光热最小技术出力、最小在线机组数、供需预检查、时变风光成本、滚动爬坡率/断面限额等由 core 校验和求解；CLI 负责忠实建模、启动及错误呈现。

## 已覆盖的公共后端工作流

- case 模板、样例、复制、导入、下载、合并、按 bus/zone 拆分。
- 单个设备 sheet 的 XLSX 导入与导出。
- case 专用时序 XLSX 模板、检查、冲突策略、插入和设备绑定。
- `.tr` 导入，报告重新生成，汇总表、详细结果和平衡结果批量下载。
- task 状态、等待、完成/未完成分页、筛选和失败日志诊断。
- `.tr` 动态 result key/设备曲线 inventory、任意时刻电力平衡、系统/分区工作位置图及带服务端设备过滤的时序读取。
- task 等待/计算取消、可编辑 case 文件删除，以及已完成 task/result 记录删除；三者使用独立命令和状态护栏。
- 市场模拟结果的路径化读取、节点边际电价及能量/阻塞分量、可选机组经济性和分电压等级价格统计。

## 通过通用模型接口覆盖

`integrated`、`interface_add`、`branch_add`、`coordinated_add`、`powerbase_add` 等专业表没有独立命令，但不是不可操作：先 `case structure`，再使用 `case sheet/row` 的显式 JSON。参数树中的新增算法开关同理使用 `case parameter get/set/patch/replace`。

这种覆盖要求服务端提供稳定 schema。CLI 不为每个模型列重复造选项，也不对未知字段填入猜测默认值。

## 有意不暴露的接口

以下能力不属于通用建模/执行客户端，或当前缺少稳定且安全的通用工作流：

- 用户、认证服务、授权、license 和权限管理；
- 系统配置、服务日志管理、后台任务管理等管理员接口；
- 设备默认参数、负荷历史库和模型库的管理面 CRUD；
- ClawUI 或其他宿主的工作区、会话、下载预览和服务地址策略；
- PSASP/BPA 导入转换、拓扑图生成/诊断等仍使用旧格式或尚未形成清晰稳定 CLI 契约的辅助接口。

“有意不暴露”不表示 core 没有该路由。不要用 `curl` 绕过 CLI；若确需纳入，先设计输入、输出、权限、幂等性和失败恢复语义，再同步 CLI、测试、skill 与兼容记录。

## 判断与升级规则

遇到未知 core 功能时：

1. 先确认它属于 case、task、result 还是管理面。
2. 检查是否已能由通用 sheet/row/parameter/result group 表达。
3. 只有稳定的多步公共工作流才增加专用命令。
4. 对照 `CHANGELOG.md` 的最后 core hash 扫描增量，同时复查当前配置和公开路由快照。
5. 同步记录已采用、改变、移除和有意排除的接口。
